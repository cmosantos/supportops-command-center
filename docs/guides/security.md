# Security and Operational Boundaries

The application accepts untrusted incident/runbook query text as inert data. It
does not use shell/subprocess, dynamic evaluation/import, command executors,
administrative actions, unsafe deserialization, LLM/vector providers or automatic
approval/action. Streamlit imports presentation/application contracts and does not
access SQLite, runbook files or exporters directly.

SQLite statements bind values, transactions roll back on failure, foreign keys are
enabled and migrations are ordered/checksummed. Knowledge resolves files under its
fixed package root. Export filenames are generated by the application, resolve
inside one configured root, publish atomically, and never overwrite.

Containers run non-root with dropped capabilities, no-new-privileges, read-only
root filesystem, loopback host publication, bounded healthcheck, tmpfs and separate
persistent data/export volumes. Protect those volumes as incident records.

Offline dependency review can enumerate locked dependencies and forbidden product
dependencies but cannot honestly assert current vulnerability-database status.
Run an approved, current vulnerability scanner before public release and review
all findings; it must not receive application secrets because none are required.
